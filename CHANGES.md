# Changes on `open-architecture/atproto-market--spec-iroh-dumbpipe-policy2-20261005`

The requirement-level delta against `open-architecture/atproto-market--spec-iroh-dumbpipe-policy2-20261005`, and what this branch realized.

## Requirements

### atproto-market

- intent: "" -> "The tests that drive the market, the gateway, the bidder and the PLC must not touch the real plc.directory or depend on a pre-provisioned dispatcher, so this context provides one installable fetch redirection plus the fixtures and factories those tests share. It exists to keep every integration test pointed at in-process fakes with a single, reversible patch, to keep generated cloud-init comparable to checked-in golden YAML, and to let the full-flow harness reproduce the same topology end to end on self-chosen ephemeral ports."
- added `r.async-watcher-tests` (MAY): "The firehose watcher and bid collector tests drive their subscriptions and collector loops against the intercepted fetch stack and stop long-running watchers inside the test process rather than requiring external services."
- added `r.bidder-policy-tests` (SHOULD): "The bidder-only-me, bidder-prod, bidder-ssh-relay and bidder-policy-only-me test modules exercise bidder selection policies and relay paths against the same intercepted stack, so policy changes are caught by tests that do not reach the production network."
- added `r.ca-trusted-https` (MUST): "When caCertPem is set the interceptor creates a Deno HttpClient with that PEM in caCerts, keeps the rewritten localhost URL on the https scheme and passes the client on the RequestInit of the realFetch call; when caCertPem is absent no client is created and the localhost URL is downgraded to http, so TLS-only paths stay testable without weakening paths that do not need it."
- added `r.cloud-init-golden-fixtures` (MUST): "The cloud-init YAML fixtures fedproxy-ssh.yaml, fedproxy-web-wootty.yaml, tunnel.yaml, tunnel-secrets.yaml, k3s.yaml and tunnel-k3s.yaml are the golden outputs that test/cloud_init_snapshot_test.ts and test/cloud_init_k3s_test.ts compare generated cloud-init against, covering the SSH relay, the web/wootty relay, the tunnel with and without injected secrets, and the k3s and tunneled-k3s user data, so those generated outputs must stay comparable to these fixtures."
- added `r.defect-regression-tests` (SHOULD): "test/defect1_gateway_did_test.ts and test/defect4_qr_session_test.ts pin the previously fixed gateway DID handling and QR session behaviours, so those regressions cannot return unnoticed."
- added `r.fetch-interceptor-export` (MUST): "test/fetch-interceptor.ts exports installFetchInterceptor(opts) taking realFetch, plcDirectoryUrl, dispPort and an optional caCertPem; it replaces globalThis.fetch with a wrapper that delegates to the supplied realFetch and returns a teardown function of type () => void, so a test can install the redirection for the duration of one case."
- added `r.full-flow-harness` (MUST): "compute-contract-full-flow/run_full_flow.ts defines its own non-exported installFetchInterceptor accepting only realFetch, plcDirectoryUrl and dispPort, with no CA support and an unconditional downgrade of the localhost leg to http; its main() serves a dispatcher app from createRelayFactory and a fake PLC on ephemeral ports bound to 127.0.0.1, resolves each bound port through an onListen callback, pushes one abort-controller cleanup per server, and logs timestamped progress lines collected into the run summary."
- added `r.integration-tests-install-interceptor` (MUST): "The integration test modules in this context - bidder container, bidder cross-platform, gateway caller-rbac, gateway readme smoke, gateway request-vm, gateway ssh, gateway worker and oauth session transfer - install the fetch interceptor before driving their flows, so every outbound plc.directory and *.localhost call in the test process is redirected to the local fake PLC and dispatcher."
- added `r.interceptor-teardown` (SHOULD): "The function returned by installFetchInterceptor restores globalThis.fetch to the original realFetch and closes the CA-trusting HttpClient when one was created, so test cases leak neither a patched global fetch nor an open client."
- added `r.localhost-port-rewrite` (MUST): "For https URLs whose host is exactly localhost, ends with .localhost, or contains .localhost:, the wrapper appends :dispPort when the host carries no port, preserves the matched path, and re-fetches through realFetch, so service DID documents pointing at *.localhost reach the ephemeral dispatcher; every URL matching neither rule is handed to realFetch unchanged with its original init."
- added `r.plc-directory-factory` (SHOULD): "hono-plc/mod.ts is the Hono PLC directory factory this repository serves, driven by the declarative files hono-plc/config.json and hono-plc/cli-args-env.json rather than by its entrypoint reading environment variables directly, so the local PLC the full-flow harness and the tests exercise is the same factory the CLI runs."
- added `r.plc-url-redirect` (MUST): "The installed wrapper detects URLs starting with https://plc.directory/, replaces that prefix with the supplied plcDirectoryUrl while keeping the remaining path, builds a Request from the rewritten URL carrying the original init when the input was not already a Request, and issues it through realFetch, so DID resolution against the real PLC host lands on the local fake PLC."
- added `r.record-shape-lexicons` (MUST): "The record shapes asserted by the tests here - fedproxy rbac and ssh public keys, badge blue keys, the market bid, bidder, receipt, offering and event records, and secrets capability records - must match the lexicon definitions the repository publishes under lexicons/, so changing an asserted record field requires the matching lexicon change."

### hono-bidder

- intent: "" -> "This context exists to pin down the runnable bidder process itself: the flag/env/default surface it accepts, the precedence rules that turn those options into a concrete identity, key material, auth mode, compute providers and relays, and the boot sequence that ends in a readiness line a supervisor or test harness can key on. It matters because the bidder's behaviour is not derivable from the libraries it composes -- ordering (attestation key before PLC genesis, relay crawl registration after the offering commit, image prebuild before first provision), failure semantics (which errors are logged warnings versus fatal exits), and the local-development escape hatches are all decisions made here, in hono-bidder/mod.ts and hono-bidder/cli-args-env.ts."
- added `r.association-qr` (MUST): "Unless --skip-qr is set, the bidder scans its own badgeBlueKeys records for an existing bidder_associate association and skips the prompt when one exists; otherwise it prints a qr.fedfork.com QR URL, waits on associateCalled, resolves the caller's handle from alsoKnownAs, prompts y/N on stdin, and either approves the association or rejects it and exits 0."
- added `r.attestation-keypair` (MUST): "An attestation keypair is derived from the same private key hex via loadOrGenerateKeypair before any PLC genesis op runs, so the attestation did:key can be published in the bidder's DID document and used as the badgeBlue signer."
- added `r.auth-mode-selection` (MUST): "Exactly one AT Protocol auth mode is chosen in this order: --atproto-oauth, which requires --atproto-handle and exits 1 with an error log when the handle is missing, using createOAuthAgent with restore, startFlow and completeFlow plus a loopback callback server; --atproto-oauth-qr, which registers a genesis did:plc on the PLC directory, restores a saved QR session when present and otherwise renders a qr.fedfork.com QR and polls for the transferred session; --atproto-handle together with --atproto-password, which creates a local PDS agent; and the default, which creates a local PDS agent and runs the association QR flow. The two OAuth modes set isOAuth true and leave pdsHostname undefined, while the two local modes set isLocal true and take pdsHostname from the relay ingress host."
- added `r.badge-blue-attestation-binding` (MUST): "After the ATProto client is built, the bidder writes a badgeBlueKeys record for itself with keyId equal to the attestation did:key and service "bidder_attestation", using createRecord rather than putRecord, which the OAuth scope rejects; a failed write is a logged warning, not a fatal error."
- added `r.bidder-serve-binding` (MUST): "The market bidder gets its own serve instance bound to options.serveAddr, which defaults to 0.0.0.0, options.servePort, which defaults to 0 for a random port, and a Unix socket at options.serveUnix when that option is set; an ingress is created for it unless --no-ingress-proxy is set."
- added `r.compute-providers` (MUST): "Compute providers are registered only when their flag is set: a DigitalOcean provider when --compute-provider-digitalocean-token is present, a local provider when --compute-provider-local is set, honoring mode, VM image, container image, cache dir, CA cert PEM and guest TLS port, and a Deno worker provider when --compute-provider-deno-worker is set. Each provider gets its own ingress with a freshly generated relay keypair and its own serve instance, and each serve is begun before startup continues."
- added `r.config-resolution` (MUST): "mod.ts resolves its options by constructing the cli-args-env Command with the environment/config path key CONFIG_PATH_HONO_BIDDER, the cli-args-env module's default export, and an optional runtime config loaded from ./config.json; a missing or unparsable config.json is tolerated and leaves the built-in defaults in force."
- added `r.container-image-prebuild` (SHOULD): "When the local provider exposes ensureImage, the bidder awaits it after the association step and logs before and after, so the first guest provision does not pay the image build cost."
- added `r.declarative-config` (MUST): "The CLI configuration is one default-exported object named "bidder" whose options map each flag to a type, a description, an optional environment variable and an optional default; that object is the only source of the flag, environment-variable and default surface that mod.ts consumes."
- added `r.deferred-relay-registration` (MUST): "PDS registration with relays is deferred until after the offering record exists: local relay URLs are re-announced once the local serve port is known, and the remaining crawl relays are announced with the visibility hostname after startup, because a crawl that connects before the offering commit would miss it in the live-stream gap."
- added `r.event-streams-relays` (MUST): "Event streams are configured from the union of --relay-url and, when --firehose-mode is "subscriberepos" and --firehose-url is set, the comma-separated firehose URLs; when firehose URLs are used the default relay list is removed, and only http(s) root URLs are retained as requestCrawl targets because wss firehose URLs are consumed by the event-streams client instead."
- added `r.graceful-shutdown` (MUST): "SIGINT and SIGTERM handlers shut the market bidder down, dispose the OAuth agent when running in an OAuth mode, shut down every provider serve, and then exit."
- added `r.ingress-per-relay-keypair` (MUST): "Each ingress created for a relay uses a freshly generated keypair, while service-auth JWTs are signed by the bidder's identity signer, whose DID is the OAuth PLC DID in QR mode and otherwise the ATProto DID."
- added `r.local-dev-fetch-patch` (SHOULD): "When the ingress proxy host looks local (localhost or 127.*) or the PLC directory URL resolves to a local host, global fetch is patched so https://*.localhost is rewritten to the ingress port over http and https://plc.directory/ is rewritten to the configured local PLC URL; otherwise fetch is left untouched."
- added `r.oauth-client-metadata-route` (MUST): "The bidder serve exposes GET /oauth-client-metadata.json returning oauthClientMetadata built from the OAuth client id, the redirect URI, the bidder OAuth scope list and the client name "Compute Provider (hono-bidder)"."
- added `r.oauth-session-expiry` (MUST): "An OAuth session-expired error handler logs the session path, deletes the stale session file when present, and exits the process with code 1 after a short flush delay so a supervisor restarts it and re-authenticates."
- added `r.offering-refresh` (MUST): "--offering-refresh-sec defaults to 300 and is converted to milliseconds for createMarketBidder; a value of 0 or less is passed as undefined so the refresh loop is disabled."
- added `r.operator-association` (MUST): "When --associate-with is set, the bidder mints a bidder_associate badgeBlueKeys record in the canonical shape challenge equal to the operator DID and keyId equal to this bidder's DID before the market bidder starts, so the trust cache resolves the bidder's operator ahead of the only-me scope check; failure is logged and does not abort startup."
- added `r.policy-config` (MUST): "Policy arguments are parsed with parsePolicyArgs, and when --policy is set the name is resolved against the policy registry with side "bidder"; an unknown or wrong-side policy name, or any parse failure, prints "invalid --policy: <error>" and exits with code 2. The resolved policy and its args are handed to createMarketBidder together with the only-remote and allow-untrusted execution flags."
- added `r.private-key-precedence` (MUST): "The bidder signing key comes from options.privateKeyHex first; only when that is absent is hex read and trimmed from the file at options.privateKeyHexPath. If neither yields a key, a fresh exportable Secp256k1Keypair is created and its hex is written back to privateKeyHexPath, creating parent directories, so later runs reuse it. Every read or write failure on that file is logged as a warning rather than being fatal."
- added `r.ready-line` (MUST): "After beginServe the bidder writes a single machine-readable JSON line to stdout containing event "bidder_ready" plus the bidder DID, the ingress ref and the serve port, so a test harness spawning the process as a subprocess can detect readiness."
- added `r.relay-visibility-check` (SHOULD): "When relay URLs and a visibility hostname are available, verifyRelayVisibility is run against the offering collection for the bidder DID; a positive result logs the indexing relays and a negative result logs a warning hinting that requester-side listReposByCollection discovery will not find this bidder. Failure never aborts boot."
- added `r.worker-permission-mode` (MUST): "The Deno worker provider defaults its worker permission mode to "deny-all"; only the value "allow-net" installs a permission policy handler, loaded dynamically."

### hono-compute-contract-gateway

- intent: "" -> "This context exists so the compute contract gateway can be run as a real process rather than only as a library: it binds the abstract ComputeContractGateway contract (lib/abc/compute-contract-gateway) and its XRPC implementation (lib/compute-contract-gateway-xrpc) plus the Hono factory (lib/hono-factory-compute-contract-gateway-xrpc) into a deployable Deno CLI. It owns process-level concerns the libraries do not: argument and environment resolution through cli-args-env.json and config.json, key material resolution from a hex string or a file path, listener and storage wiring, DID and IdResolver setup, HTTP mounting, readiness logging, and graceful teardown on signals. It also owns the README-driven integration contract, expressed as a subprocess smoke test that proves the documented shell blocks actually work."
- added `r.command-entrypoint` (MUST): "mod.ts runs as the process entrypoint and resolves its options by constructing Command("CONFIG_PATH_HONO_COMPUTE_CONTRACT_GATEWAY", cli-args-env.json, runtimeConfig).resolve(), where runtimeConfig is the default export of ./config.json when that file exists and is null when the import fails, so the package starts with or without a local config file."
- added `r.config-surface` (MUST): "The CLI exposes exactly these options, each reading its flag or the named environment variable: port (env PORT, no default, no TCP listener when unset), hostname (env HOSTNAME, default localhost, also supplied by config.json), private-key-hex (env PRIVATE_KEY_HEX, no default), private-key-hex-path (env REPO_PRIVATE_KEY_HEX_PATH, no default), pds-state-path (env PDS_STATE_PATH, no default), plc-directory-url (env PLC_DIRECTORY_URL, default https://plc.directory), ingress-proxy-host (env INGRESS_PROXY_HOST, default xrpc.fedproxy.com), fedproxy-host (env FEDPROXY_HOST, default fedproxy.com), relay-urls (env RELAY_URLS, no default), and storage-path (env STORAGE_PATH, no default)."
- added `r.deno-package-manifest` (MUST): "deno.json declares the package's JSR imports for cli-args-env, compute-contract-gateway-xrpc, hono-factory-compute-contract-gateway-xrpc, logger, serve and @atproto/identity, and compiles cli-args-env.json and config.json into any compiled binary so the config surface survives compilation."
- added `r.gateway-contract-consumed` (MUST): "The CLI depends on the ComputeContractGateway contract and exposes its whole surface over HTTP: a did getter, beginServe and dispose lifecycle calls, and the requestComputeVM, requestComputeWorkerEphemeral, requestComputeWorkerPersistent and deleteCompute operations invoked with a CallerIdentity and receipt inputs, so the CLI adds no operation the contract does not define."
- added `r.gateway-startup` (MUST): "The gateway is built with createComputeContractGateway using the resolved logger, serve instance, private key, PLC directory URL, ingress proxy host, fedproxy ingress host and storage path under the fixed label compute-contract-gateway, and gateway.beginServe() is awaited before the HTTP app is constructed so the gateway DID exists first."
- added `r.graceful-shutdown` (MUST): "SIGINT and SIGTERM both log gateway_shutting_down, await gateway.dispose() and then call Deno.exit(0), so the gateway is torn down rather than killed mid-write."
- added `r.http-mount-and-ready` (MUST): "The factory's Hono app is mounted at the root of the serve instance with serve.app.route("/", app) and serve.beginServe() is awaited, after which a gateway_cli_ready event is logged carrying the gateway DID, so readiness is observable from the event stream rather than inferred from process liveness."
- added `r.identity-and-audience` (MUST): "An IdResolver is constructed with plcUrl defaulting to https://plc.directory, and the Hono factory is called with that resolver, hostname defaulting to localhost, and audienceDids set to the running gateway's own DID, so service-auth tokens addressed to this gateway are accepted."
- added `r.private-key-resolution` (MUST): "The private key is taken from private-key-hex when present; only when that is empty and private-key-hex-path is set does the process read that file, trim its contents and log key_loaded_from_path with the path and key length, and a read failure is swallowed so a missing key file still lets the gateway generate a key."
- added `r.readme-block-coverage` (SHOULD): "The README shell blocks the smoke test must exercise are the Quick Start server start plus health check, the VM key generation and requestComputeVM call, and the worker heredoc setup with requestComputeWorkerEphemeral and requestComputeWorkerPersistent calls, each expected to exit zero with the CLI started as a real subprocess against local infrastructure and no external network."
- added `r.readme-smoke-task` (SHOULD): "deno.json provides a test:readme task that runs deno test -A against test/gateway_readme_smoke_test.ts using the repository root deno.json as its config, giving the README contract a single reproducible command."
- added `r.relay-urls-parsing` (MUST): "The relay-urls option is a comma-separated string that is split on commas, trimmed per entry, and passed as an array, defaulting to an empty array when the option is absent."
- added `r.storage-path-fallback` (MUST): "The storage path handed to the gateway is pds-state-path when set, otherwise storage-path, so the persistent PDS state location can be overridden independently of general storage."
- added `r.tcp-listener` (MUST): "The serve instance is created with a TCP listener only when port is set, binding that port on hostname or 0.0.0.0 when hostname is absent; with no port the serve instance carries no TCP listener."

### hono-market

- intent: "" -> "This context exists to pin down what hono-market is for: nothing. It marks the package as a deliberate stub so that readers and tooling do not go looking for a Hono app, an XRPC handler, or a market client here, and so that the market behaviour owned by the Hono market factory and the market-atproto client is not duplicated into this package. The specification is therefore mostly prohibitive: the module stays empty, the manifest stays minimal, and the real market surface stays where it lives."
- added `r.empty-entry-module` (MUST): "The package entry module hono-market/mod.ts is a valid ES module with no exports; it must not define or re-export any value, type, factory, or handler, and must produce no side effects, so importing the package leaves a consumer with nothing to bind and no behaviour to observe."
- added `r.manifest-stays-minimal` (MUST): "The package manifest hono-market/deno.json must carry no imports, no tasks, and no export mappings, so the stub resolves under Deno's defaults and exposes no entry point beyond the empty mod.ts."
- added `r.no-market-behaviour` (SHOULD): "Market HTTP and market client behaviour must stay in the packages that own it, the Hono market factory and the market-atproto client, rather than being copied into this package, so no Hono factory, XRPC handler, or market client is duplicated or re-exported from hono-market."
