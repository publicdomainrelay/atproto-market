# Changes on `open-architecture/atproto-market--spec-iroh-dumbpipe-policy2-20261005`

The requirement-level delta against `open-architecture/atproto-market`, and what this branch realized.

## Requirements

### atproto-market

- intent: "The tests that drive the market, the gateway, the bidder and the PLC must not touch the real plc.directory or depend on a pre-provisioned dispatcher, so this context provides one installable fetch redirection plus the fixtures and factories those tests share. It exists to keep every integration test pointed at in-process fakes with a single, reversible patch, to keep generated cloud-init comparable to checked-in golden YAML, and to let the full-flow harness reproduce the same topology end to end on self-chosen ephemeral ports." -> "The tests that drive the market, the gateway, the bidder and the PLC must not touch the real plc.directory or depend on a pre-provisioned dispatcher, so this context provides one installable fetch redirection plus the fixtures and factories those tests share. It exists to keep every integration test pointed at in-process fakes with a single, reversible patch, to keep generated cloud-init comparable to checked-in golden YAML, and to let the full-flow harness reproduce the same topology end to end on self-chosen ephemeral ports. It also owns the one suite that has to prove the iroh transport for real: the container integration test drives a complete RFP-to-SSH contract against a Docker guest whose cloud-init the RFP itself composed, so the transport the spec claims is the transport the suite exercises."
- added `r.iroh-acceptance-flow` (MUST): "test/bidder_container_integration_test.ts must prove the iroh transport end to end instead of racing a timer. It drives runComputeContract through RFP, bid, accept and cloud-init with skipSsh false, and awaits the whole contract promise with no Promise.race and no wall-clock deadline; its servers, bidder, provider and requester are torn down only after that promise settles, so provisioning is never torn down while it runs. It then asserts the run reached the guest over the transport the RFP cloud-init deployed: sshReady true, sshExitCode 0, result.sshProxyCommand naming the dumbpipe connect command for the ticket the guest reported (never a websocat ProxyCommand and never a direct address), and a program run inside the guest that exits 0 and whose output carries the marker SSH_OK_VIA_IROH. The suite must not read the guest's ticket or address out of the guest by any host-side side channel such as executing a command against the container: the ticket reaches the requester only through the guest's own outbound report or a vm.onNetwork event, and every SSH byte path goes through the transport ProxyCommand. Capturing the marker is allowed to require a small addition to the flow's result (for example an optional captured session output) rather than an assertion on the exit code alone, and this test must not be skipped: it is the acceptance suite."
- added `r.iroh-acceptance-plc-key-resolution` (MUST): "The fake PLC the container integration test serves must let a did:plc DID be resolved to its atproto signing key, because the relay authenticates the requester's subscriber registration by resolving that DID and the market verifies receipt signatures the same way. Resolving a did:plc DID through the fake PLC must return a DID document whose verification method yields that DID's did:key, and the resolution must work end to end through whatever resolver the relay and the market actually call (including the atproto identity resolver and the did:key fast path), so that the relay's registration call succeeds rather than answering 401 and receipt verification passes. The suite must assert the registration and the receipt explicitly, so a resolution failure fails the test instead of silently degrading the run."
- added `r.iroh-cloud-init-fixture` (MUST): "The composed iroh guest is pinned by a golden fixture: test/fixtures/cloud-init/iroh.yaml is the byte-exact output of the cloud-init composer for the iroh module with its context fields set, and test/cloud_init_snapshot_test.ts gains a case comparing the generated output against it plus semantic assertions that the YAML installs the pinned dumbpipe release, starts the loopback listener, carries the guest's ticket report to the configured report URL, and configures the sshd it installs. The existing six fixtures stay byte-identical and `deno test -A test/cloud_init_snapshot_test.ts` must pass."
- added `r.iroh-full-flow-harness` (SHOULD): "compute-contract-full-flow/run_full_flow.ts must keep running under the new default. Because it calls runComputeContract with skipSsh false, it must either let the iroh default compose the guest and reach it by ticket (bootstrapping the dumbpipe helper the session provider needs) or select the tunnel transport explicitly and keep the websocat topology. Its header diagram and progress lines must describe the transport the script actually uses, so the printed topology cannot still claim a websocat ProxyCommand after the default changed, and it must not import or call a helper the change removed."

### lib-abc-requester

- intent: "This context exists so the atproto-market requester's ABC layer — the bid collection and winner-selection rules, the requester PDS surface, the contract flow's option and result bags, and the SSH session provider contract — can be specified once and depended on by the implementation, the CLI and the hermetic test fakes without any of them re-deriving the shapes. It is a pure declaration file: no I/O, no runtime globals, only the types and pure helpers that the transport layers below it must satisfy." -> "This context exists so the atproto-market requester's ABC layer — the bid collection and winner-selection rules, the requester PDS surface, the contract flow's option and result bags, and the SSH session provider contract — can be specified once and depended on by the implementation, the CLI and the hermetic test fakes without any of them re-deriving the shapes. It is a pure declaration file: no I/O, no runtime globals, only the types and pure helpers that the transport layers below it must satisfy. The guest transport is iroh by default, so the address the flow waits for and hands to the SSH provider is an opaque transport address — an iroh ticket for iroh, a relay hostname for the websocket transports — and the ABC layer never assumes it is a resolvable FQDN."
- changed `r.bid-collector-dedupe` (codeRefs): "BidCollector.add ignores a bid whose uri has already been seen and otherwise records that uri, appends the bid and starts the early-exit path only when firstFree is set, the collector is unsettled and isFree(bid) holds; addAll is a repeated add over an array and all() returns the arrival-ordered list of distinct bids, so two bidders submitting the same record URI contribute one entry."
- changed `r.bid-collector-drain` (codeRefs): "drain waits for every in-flight early-path policy check to settle by looping over Promise.allSettled of the tracked in-flight set until it is empty, so a caller that stops waiting out the bid window still observes all policy checks complete before it proceeds, and no rejection from a check escapes drain."
- changed `r.bid-collector-early-winner` (codeRefs): "On the early-exit path add awaits opts.allow(bid) and, only if that policy gate resolves true and no earlier free bid has settled the collector, sets the settled flag, invokes opts.onEarlyWinner and resolves the public earlyWinner promise with that bid; a rejected gate is swallowed by a catch and leaves the window open, so a free bid from a rejected bidder never short-circuits it."
- changed `r.bid-collector-early-winner-once` (codeRefs): "earlyWinner is created through Promise.withResolvers in the constructor and settles at most once per collector, because the settled flag is re-checked after the allow promise resolves, so a second free bid arriving while the first policy check is still in flight can never produce a second resolution or a second onEarlyWinner callback."
- changed `r.bid-collector-options` (codeRefs): "BidCollector is constructed from a BidCollectorOptions whose freeBidNsid, firstFree and async allow gate are required and whose onEarlyWinner callback is optional, so every caller must name the NSID that marks a bid free and supply the policy gate; isFree is exactly the comparison of bidPayloadNsid(bid) against that freeBidNsid."
- changed `r.bid-cost` (codeRefs): "bidCost reads record.payload.cost and coerces it with Number, yielding Infinity when the payload or the cost is absent, so an unpriced bid never wins on price and never returns NaN into the comparison."
- changed `r.bid-payload-nsid` (codeRefs): "bidPayloadNsid reads the NSID from record.payload: it returns the payload's $type when a $type is present and is not com.atproto.repo.strongRef, otherwise it falls back to the fourth slash-separated segment of payload.uri (the rkey position of an at:// URI), and it returns the empty string when there is no payload or no such segment."
- changed `r.collected-bid-shape` (codeRefs): "A collected bid is identified by exactly four fields, did, uri, cid and an untyped record object; the bid's payload and cost are read out of that record by bidPayloadNsid and bidCost rather than carried as top-level fields, so callers pass the raw atproto record through untouched."
- changed `r.console-buffer` (codeRefs): "ConsoleBuffer lets the flow stop and restart console output around interactive or SSH phases: pause is synchronous and resume returns a promise the caller awaits before the flow continues."
- changed `r.contract-flow-defaults` (text): "The option bag documents its own defaults so implementations agree: fedingressHost defaults to fedproxy.com, the userData transport module defaults to the iroh module id (the dumbpipe listener transport), and sshProxyCommandFn, when supplied, overrides the per-target ProxyCommand that otherwise follows the transport the flow selected — `dumbpipe connect <ticket>` for iroh and websocat --binary wss://<fqdn> only for the explicitly selected tunnel or fedproxy-ssh transport — letting tests and alternate ingress topologies rewrite the guest endpoint while keeping the RFP flow intact."
- changed `r.contract-flow-result` (codeRefs): "ContractFlowResult reports the terminal event name plus whichever URIs and CIDs the run produced (vm, rfp, accept, bid and receipt), the winner DID, the submit event reference and receiptOk flag, the bid count, sshReady and sshExitCode, and an error string; every field other than event is optional, so partial results can be returned for a failed run."
- added `r.contract-flow-result-transport` (MUST): "ContractFlowResult also carries the transport the run actually used: an optional sshProxyCommand string holding the ProxyCommand the SSH provider was given or derived for the guest target (e.g. `dumbpipe connect <ticket>` for iroh), so a caller can assert how the guest was reached without re-deriving it from the options. The field is optional and absent on a run that never attempted SSH."
- changed `r.pds-options` (codeRefs): "PDSOptions requires a structured logger and a serve handle and accepts optional privateKeyHex, plcDirectoryUrl, ingressProxyHost, label, storagePath and skipIngress, so a requester PDS can be built against an existing serve handle with or without its own ingress and with optional durable storage."
- changed `r.requester-pds-association` (codeRefs): "RequesterPDS carries the CLI association handshake: associateCalled resolves with the caller DID when the webapp invokes the associateConfirm XRPC, while approveAssociation resolves that pending XRPC response and rejectAssociation rejects it with the supplied error."
- changed `r.requester-pds-bidder-calls` (codeRefs): "RequesterPDS resolves a bidder's endpoint from an endpoint URL to a target URL plus audience DID, or null when it cannot be resolved, and calls it through callBidder with a target base, NSID, lxm, audience DID and body, returning the raw status, ok flag and decoded body so the flow never speaks HTTP itself; incoming bids are buffered in a pendingBids map keyed by the contract uri."
- changed `r.requester-pds-ingress-lifecycle` (codeRefs): "RequesterPDS exposes did, serve and relay immediately, but ingressRef, relaySubdomain, ingressUrl and ingressHost are valid only after beginServe() has been awaited; before the relay connects the URL and host accessors return the empty string rather than throwing."
- changed `r.requester-pds-optional-handles` (codeRefs): "RequesterPDS exposes dispose() to release storage resources such as a Deno.Kv handle, and carries optional irohNodeId, resolveIrohNodeId, setOnNetworkResolved and clearOnNetworkResolved members: the iroh node id promise is resolved once and is a no-op after the first call, and onNetwork interest is keyed by the contract's receipt because one requester serves many contracts concurrently."
- changed `r.requester-pds-records` (codeRefs): "RequesterPDS writes to its own repo through createRepoRecord and createSignedRepoRecord, both returning the created record's uri and cid; the signed variant additionally takes an attestation keypair and an optional issuer so a record can be attributed to a key other than the repo owner, and the interface exposes that attestationKp plus the requester's signer and privateKeyHex as properties."
- added `r.requester-pds-transport-address` (MUST): "RequesterPDS is the only channel through which the flow learns where the provisioned guest can be reached, and it learns one transport address per contract: the flow registers its interest keyed by the contract's receipt before the guest is provisioned, the PDS resolves that interest exactly once, and a second address for the same contract is ignored. The address is opaque — an iroh ticket for the default transport and a relay hostname for the websocket transports — so the PDS must not classify, rewrite or reject it by shape. The same PDS owns the inbound route the guest POSTs its own address to and exposes the absolute URL of that route so the flow can bake it into the guest's cloud-config; a requester with no publicly addressed ingress exposes no such URL and leaves the flow waiting on the event path instead."
- changed `r.select-winner-cheapest` (codeRefs): "selectWinner returns the bid with the strictly lowest bidCost by reducing over the array, keeping the earliest of equal-cost bids because the incumbent is replaced only on a strict less-than, and it returns undefined for an empty bid list."
- changed `r.ssh-session-provider` (codeRefs, text): "SshSessionProvider is the whole SSH surface the flow may assume: generateKeypair returns a public key and a private key path for a VM name, pollReady reports whether the guest at a transport address becomes reachable within a timeout, and runSession runs a program on that address and returns its exit code. The address argument is the guest's transport address, not necessarily a DNS name: an iroh ticket for the iroh transport and a relay hostname for the websocket transports. The provider, not the flow, turns that address into a ProxyCommand, so a provider and the flow agree on key material, readiness and exit status without the flow knowing the transport or how the address is dialled."

### lib-did-key-ingress-proxy

- intent: "This context exists so a local XRPC app can be reached from outside without owning a routable address: createIngress bundles subscriber registration, per-method service-auth minting, WebSocket target resolution and shutdown behind one IngressRef, letting a dispatcher publish an ingress identity on an ingress proxy host and hand inbound relay requests back into its own fetch handler. The options record keeps the two signing identities separable and leaves TLS, the lazily resolved loopback target and the in-process direct subscription handler as opt-in knobs, so the same factory serves a TLS-terminated public dispatcher and a test process with an in-memory firehose source." -> "This context exists so a local XRPC app can be reached from outside without owning a routable address: createIngress bundles subscriber registration, per-method service-auth minting, WebSocket target resolution and shutdown behind one IngressRef, letting a dispatcher publish an ingress identity on an ingress proxy host and hand inbound relay requests back into its own fetch handler. The options record keeps the two signing identities separable and leaves TLS, the lazily resolved loopback target and the in-process direct subscription handler as opt-in knobs, so the same factory serves a TLS-terminated public dispatcher and a test process with an in-memory firehose source. It is the requester's control plane only: the market XRPC calls, the requester's own mounted routes and the websocket tunnel stay here, while the SSH data plane to a provisioned guest is carried by iroh and no longer routes through this package."
- added `r.control-plane-and-report-route` (MUST): "createIngress is the requester's control plane and its only public face: the relay carries the market XRPC calls (submitBid, submitEvent, associateConfirm) and every route the requester mounts on its own app, so a route mounted on the requester's serve is reachable at the relay's ingress URL even though the requester owns no routable address — which is what makes the inbound route a provisioned guest POSTs its transport address to reachable. The websocket tunnel target (localWsTarget and the subscriber tunnel) stays available and unchanged for callers that explicitly select the tunnel or fedproxy-ssh transport, but the SSH data plane no longer depends on this package: an iroh guest is reached by ticket through dumbpipe, never through the subscriber tunnel, and nothing host-side reads the guest's address out of the relay."

### lib-hono-factory-did-plc-directory

- changed `r.export-pagination` (codeRefs): "The export handler reads the after and count query parameters, rejecting an after that does not parse as a date with 400 'Invalid Query Parameter: after' and a count that is non-numeric or negative with 400 'Invalid Query Parameter: count', clamping an accepted count to at most 1000, and answers with the entries returned by store.exportLogs(after, count)."
- changed `r.memory-store` (codeRefs): "MemoryPlcStore implements PlcStore over an in-process Map keyed by DID: getCurrentOps filters out entries flagged nullified, getAuditLog returns the stored list unchanged, getOpByCid finds an entry by CID or returns null, insertOp appends and creates the DID's list on first write, nullifyOps marks every entry whose CID is in the requested set, and exportLogs gathers entries from every DID, skips those whose createdAt is at or before an after cutoff, sorts by createdAt string order and slices to count when count is given."
- changed `r.store-contract` (codeRefs): "PlcStore is the persistence contract the directory runs against: per DID it yields the current, non-nullified operations through getCurrentOps and the full log including nullified entries through getAuditLog, looks up a single entry by CID through getOpByCid, appends an entry through insertOp, marks a set of CIDs nullified through nullifyOps, and exports entries across all DIDs in ascending createdAt order through exportLogs while applying an optional after cutoff and truncating to an optional count."
