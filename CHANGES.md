# Changes on `open-architecture/atproto-market--spec-iroh-dumbpipe-20261004141803`

The requirement-level delta against `open-architecture/atproto-market`, and what this branch realized.

## Requirements

### atproto-market

- intent: "" -> "This context exists so that the marketplace packages do not each re-implement identity, signing, PLC and record-write plumbing. createATProto centralizes how the repo obtains an agent bound to a DID and signer and how records are created and updated against arbitrary collections, while createMarketClient centralizes construction of the market XRPC client over a service. Downstream packages (bidders, gateways, market settlement, trust graph, requester) depend on these two factories rather than on raw agents or raw XRPC services."
- added `r.agent-factory` (MUST): "createATProto accepts a CreateATProtoOpts bundle of logger, badgeBlueSigner, plcDirectory and agent, and resolves to an ATProto whose DID and signer are read from the supplied agent; it constructs an IdResolver and returns record helpers bound to that agent's DID."
- added `r.attestation-signer` (SHOULD): "Attestation signing is supplied to the agent factory as an AttestationKeypair rather than as a raw key, keeping key material behind the market attestation abstraction."
- added `r.deno-workspace` (MUST): "The repository is a Deno workspace: dependencies and tasks are declared in deno.json with the resolved graph committed as deno.lock, and LEXICONS.md documents the lexicon set the packages implement."
- added `r.market-client-factory` (MUST): "createMarketClient takes an XrpcService plus an optional MarketClientOptions defaulting to an empty object and returns a MarketClient instance constructed from those two arguments, so callers never build the class directly."
- added `r.plc-directory` (SHOULD): "DID and PLC handling is injected as a PlcClient from lib/did-plc/client.ts, so the atproto helpers depend on the repository's own PLC client instead of constructing one internally."
- added `r.record-create` (MUST): "The createRecord helper mints a new rkey via TID.next().toString(), calls agent.createRecord(did, collection, rkey, record) when that method exists, and otherwise falls back to agent.applyWrites with a create action followed by agent.getRecord; both paths return a com.atproto.repo.strongRef whose uri is at://<did>/<collection>/<rkey> and whose cid falls back to the empty string when the fetched record has none."
- added `r.record-update` (MUST): "The updateRecord helper takes an existing rkey, calls agent.putRecord(did, collection, rkey, record) when that method exists, and otherwise falls back to agent.applyWrites with an update action followed by agent.getRecord; it returns the same com.atproto.repo.strongRef shape as createRecord, including the empty-string cid fallback."

### compute-contract-full-flow

- intent: "" -> "This context exists as an end-to-end integration harness: it is the executable proof that requester, bidder, provider, relay/dispatcher, PDS, and PLC pieces from the sibling packages actually compose into a successful compute contract (RFP -> bid -> accept -> receipt -> SSH) without any external infrastructure. The script exists to be run manually (`deno run --allow-all compute-contract-full-flow/run_full_flow.ts` from the polyrepo root) and to leave behind machine-readable evidence (`atproto-records.json`, `full-flow.log`) plus a human-readable `SUMMARY.md`, which is why those tracked outputs sit in the same directory."
- added `r.cleanup-reverse-order` (MUST): "Registered cleanups run in reverse registration order, each wrapped in a `try/catch` so one failure cannot stop the rest, followed by a 200 ms settle delay before the flow logs completion."
- added `r.collect-records-both-repos` (MUST): "After the contract returns, `collectRecords` paginates `listRecords` (limit 100 with cursors) for both the requester and bidder repos across the fixed collections `...market.offering`, `...market.rfp`, `...market.bid`, `...market.accept`, `...market.receipt`, `...market.policy`, `...auth.allowlist.rbacDid`, and `...compute.vm`, tagging each record with source label, DID, collection, uri, cid and value; a failure on one collection is logged as `collect error (...)` and does not abort the run."
- added `r.entrypoint-runs-standalone` (MUST): "The module is a directly runnable Deno script (shebang `deno run --allow-all`) that performs the whole flow inside `main()` and exits non-zero via `Deno.exit(1)` after logging `FATAL: <err>` if any uncaught error escapes."
- added `r.fake-plc-did-documents` (MUST): "`createFakePlc` provides an in-memory DID directory: `POST /*` stores the posted operation keyed by the URL-decoded path DID, and `GET /*` returns 404 `DID not found: <did>` when absent, otherwise renders a DID document with the two W3C contexts, the stored `alsoKnownAs`, each `verificationMethods` entry as a `Multikey` whose `publicKeyMultibase` strips a leading `did:key:`, and each `services` entry as an `#<name>` service with its type and endpoint."
- added `r.fetch-interceptor-local-routing` (MUST): "`installFetchInterceptor` replaces `globalThis.fetch` so requests to `https://plc.directory/` are rewritten to the supplied local PLC base URL, and requests whose host is `localhost`, ends in `.localhost`, or contains `.localhost:` are rewritten to plain `http://` on the dispatcher port (defaulting the port when the host carries none); it returns a restore function that puts the original fetch back, and that restore is registered as a cleanup."
- added `r.no-cli-configuration` (SHOULD): "The script exposes no CLI flags or environment variables: every knob (hostnames, ports, policy, timeouts, collection list, output paths) is fixed in source, so running it requires no arguments beyond `--allow-all`."
- added `r.participants-on-ephemeral-ports` (MUST): "The flow starts every participant in-process on loopback: the dispatcher and fake PLC on port 0 (their real ports read back through `onListen` resolvers), a bidder PDS agent (`createLocalPDSAgent`) plus a bidder ingress relay and `createMarketBidder` with a local compute provider wrapped by `createComputeProviderHooks`, and a requester PDS via `createRequesterPDS` labelled `requester`; each server's abort/shutdown closure is pushed onto `cleanups`."
- added `r.run-contract-fixed-policy` (MUST): "`runComputeContract` is invoked on the requester with the `only-me` policy and `bidWindowSec: 15`, `skipSsh: false`, `keepVm: true`, `vmReadyTimeoutSec: 60`, `execProgram: "hostname"`, an SSH session provider from `createSshSessionProvider(logger)`, the bidder DID in `extraBidderDids`, and `did:plc:centraldefaultbidder000000` in `denyBidderDids`; the returned contract object is serialized into the log."
- added `r.tracked-outputs-committed` (MAY): "The generated `SUMMARY.md`, `atproto-records.json` and `full-flow.log` are tracked alongside the script as the recorded evidence of the run described in the summary's Participants, Result and record-count sections."
- added `r.write-three-artifacts` (MUST): "The run writes exactly three files derived from the script's own directory (`new URL(".", import.meta.url).pathname`): `full-flow.log` with the timestamped log lines, `atproto-records.json` with the collected records pretty-printed, and a generated `SUMMARY.md` containing the requester/bidder DID table, the pretty-printed contract JSON, dispatcher and PLC addresses, a per-collection record-count table, links to the other two artifacts, the reproduce command, the architecture diagram and the SSH tunnel path, stamped with a generation timestamp."

### hono-bidder

- intent: "" -> "It exists so an operator can run a bidder as a single process — pick an identity/auth mode, enable compute backends, serve XRPC over TCP/Unix with an optional fedproxy ingress, and stay discoverable on AT Protocol relays — without writing any glue code. The declarative config file keeps every flag, env var and default in one auditable place, and mod.ts is the only place that interprets them."
- added `r.association-qr` (MUST): "Unless --skip-qr is set, the bidder scans its own badgeBlueKeys records for an existing bidder_associate association and skips the prompt when one exists; otherwise it prints a qr.fedfork.com QR URL, waits on associateCalled, resolves the caller's handle from alsoKnownAs, prompts y/N on stdin, and either approves the association or rejects it and exits 0."
- added `r.attestation-keypair` (MUST): "An attestation keypair is derived from the same private key hex via loadOrGenerateKeypair before any PLC genesis op runs, so the attestation did:key can be published in the bidder's DID document and used as the badgeBlue signer."
- added `r.auth-mode-selection` (MUST): "Exactly one AT Protocol auth mode is chosen in this order: (1) --atproto-oauth, which requires --atproto-handle and exits 1 with an error log when the handle is missing, using createOAuthAgent plus restore/startFlow/completeFlow with a loopback callback server; (2) --atproto-oauth-qr, which registers a genesis did:plc on the PLC directory, restores a saved QR session if present, and otherwise renders a qr.fedfork.com QR and polls for the transferred session; (3) --atproto-handle plus --atproto-password, which creates a local PDS agent; (4) the default, which creates a local PDS agent and runs the association QR flow. Modes 1 and 2 set isOAuth true and leave pdsHostname undefined; modes 3 and 4 set isLocal true and take pdsHostname from the relay ingress host."
- added `r.badge-blue-attestation-binding` (MUST): "After the ATProto client is built, the bidder writes a badgeBlueKeys record for itself with keyId equal to the attestation did:key and service "bidder_attestation", using createRecord (never putRecord, which the OAuth scope rejects); failure to write is a logged warning, not a fatal error."
- added `r.bidder-serve-binding` (MUST): "The market bidder gets its own serve instance bound to options.serveAddr (default 0.0.0.0), options.servePort (default 0 for a random port) and, when set, a Unix socket at options.serveUnix; its ingress is created unless --no-ingress-proxy is set."
- added `r.compute-providers` (MUST): "Compute providers are registered only when their flag is set: a DigitalOcean provider when --compute-provider-digitalocean-token is present, a local provider when --compute-provider-local is set (honoring mode, VM image, container image, cache dir, CA cert PEM and guest TLS port), and a Deno worker provider when --compute-provider-deno-worker is set. Each provider gets its own ingress (with a freshly generated relay keypair) and serve instance, and each serve is begun before startup continues."
- added `r.config-resolution` (MUST): "mod.ts resolves options by constructing the cli-args-env Command with the environment/config path key CONFIG_PATH_HONO_BIDDER, the cli-args-env module's default export, and an optional runtime config loaded from ./config.json; a missing or unparsable config.json is tolerated and leaves the built-in defaults in force."
- added `r.container-image-prebuild` (SHOULD): "When the local provider exposes ensureImage, the bidder awaits it after the association step and logs before and after, so the first guest provision does not pay the image build cost."
- added `r.declarative-config` (MUST): "The CLI config is a single default-exported object named "bidder" whose options map each flag to a type, description, optional env var and optional default, and that object is the only source of the flag/env/default surface consumed by mod.ts."
- added `r.deferred-relay-registration` (MUST): "PDS registration with relays is deferred until after the offering record exists: local relay URLs are re-announced once the local serve port is known, and the remaining crawl relays are announced with the visibility hostname after startup, because a crawl that connects before the offering commit would miss it in the live-stream gap."
- added `r.event-streams-relays` (MUST): "Event streams are configured from the union of --relay-url and, when --firehose-mode is "subscriberepos" with --firehose-url set, the comma-separated firehose URLs; when firehose URLs are used the default relay list is removed, and only http(s) root URLs are retained as requestCrawl targets because wss firehose URLs are consumed by the event-streams client instead."
- added `r.graceful-shutdown` (MUST): "SIGINT and SIGTERM handlers shut the market bidder down, dispose the OAuth agent when in an OAuth mode, shut down every provider serve, and then exit."
- added `r.ingress-per-relay-keypair` (MUST): "Each ingress created for a relay uses a freshly generated keypair, while service-auth JWTs are signed by the bidder's identity signer, whose DID is the OAuth PLC DID in QR mode and otherwise the ATProto DID."
- added `r.local-dev-fetch-patch` (SHOULD): "When the ingress proxy host looks local (localhost or 127.*) or the PLC directory URL resolves to a local host, global fetch is patched so https://*.localhost is rewritten to the ingress port over http and https://plc.directory/ is rewritten to the configured local PLC URL; otherwise fetch is untouched."
- added `r.oauth-client-metadata-route` (MUST): "The bidder serve exposes GET /oauth-client-metadata.json returning oauthClientMetadata built from the OAuth client id, redirect URI, the bidder OAuth scope list and the client name "Compute Provider (hono-bidder)"."
- added `r.oauth-session-expiry` (MUST): "An OAuth session-expired error handler logs the session path, deletes the stale session file if present, and exits the process with code 1 after a short flush delay so a supervisor restarts it and re-authenticates."
- added `r.offering-refresh` (MUST): "--offering-refresh-sec defaults to 300 and is converted to milliseconds for createMarketBidder; a value of 0 (or less) is passed as undefined so the refresh loop is disabled."
- added `r.operator-association` (MUST): "When --associate-with is set, the bidder mints a bidder_associate badgeBlueKeys record in the canonical shape challenge=operator DID, keyId=this bidder's DID before the market bidder starts, so the trust cache resolves the bidder's operator ahead of the only-me scope check; failure is logged and does not abort startup."
- added `r.policy-config` (MUST): "Policy arguments are parsed with parsePolicyArgs, and when --policy is set the name is resolved against the policy registry with side "bidder"; an unknown or wrong-side policy name, or any parse failure, prints "invalid --policy: <error>" and exits with code 2. The resolved policy and args are handed to createMarketBidder together with the only-remote and allow-untrusted execution flags."
- added `r.private-key-precedence` (MUST): "The bidder signing key comes from options.privateKeyHex first; only when that is absent is the hex read and trimmed from the file at options.privateKeyHexPath. If neither yields a key, a fresh exportable Secp256k1Keypair is created, and the resulting hex is written back to privateKeyHexPath (creating parent directories) so later runs reuse it. Every failure to read or write that file is logged as a warning rather than fatal."
- added `r.ready-line` (MUST): "After beginServe, the bidder writes a single machine-readable JSON line to stdout containing event "bidder_ready" plus the bidder DID, the ingress ref and the serve port, so a test harness spawning the process as a subprocess can detect readiness."
- added `r.relay-visibility-check` (SHOULD): "When relay URLs and a visibility hostname are available, verifyRelayVisibility is run against the offering collection for the bidder DID; a positive result logs the indexing relays and a negative result logs a warning with the hint that requester-side listReposByCollection discovery will not find this bidder. Failure never aborts boot."
- added `r.worker-permission-mode` (MUST): "The Deno worker provider defaults worker permission mode to "deny-all"; only the value "allow-net" installs a permission policy handler, loaded dynamically."
